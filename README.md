# منصة الرحمن للنقل الجامعي

تطبيق ويب عربي (RTL) لإدارة اشتراكات نقل الطلاب والرحلات والمدفوعات، مع بوابات للطالب والسائق والإدارة، وتطبيق أندرويد عبر Capacitor.

- الواجهة: React 19 + Vite + Tailwind CSS 4
- الخادم: Express تحت `tsx` (الملف `server.ts` ومجلد `server/`)
- قاعدة البيانات: SQLite محلية (`node:sqlite`) في `data/alrahman.db`، مع محوّل اختياري لـ PostgreSQL عند ضبط `DATABASE_URL`

## المتطلبات

- Node.js **22.13 أو أحدث** (أو 24)، لأن الخادم يستخدم الوحدة المدمجة `node:sqlite`. هذا الشرط من معرفتي بالوحدة ولم أجرّبه.
- مدير حزم واحد: **bun** (يطابق ملف القفل `bun.lock` المرفق) أو **npm**.

## التثبيت

```bash
bun install          # يستخدم bun.lock كما هو
# أو
npm install          # سينشئ package-lock.json جديدًا، ولا يوجد ملف قفل لـ npm في هذا الأرشيف
```

## الإعداد (قبل أول تشغيل)

أنشئ ملف `.env.local` في جذر المشروع. لا تُرفعه إلى أي مستودع، فهو مستثنى في `.gitignore`.

| المتغير | الاستخدام |
|---|---|
| `PLATFORM_OWNER_INIT_PASSWORD` | **ضروري ضبطه قبل أول تشغيل.** يحدد كلمة مرور حساب مالك المنصة عند إنشاء قاعدة جديدة |
| `PORT` | منفذ الخادم، والافتراضي 3000 |
| `RESEND_API_KEY` و`MAIL_FROM` | إرسال البريد الفعلي، وبدونهما لا يُرسل بريد خارجي |
| `DATABASE_URL` | تفعيل PostgreSQL (مثل Cloud SQL) بدل SQLite المحلية |
| `DATABASE_SSL` | ضبط SSL لاتصال PostgreSQL |
| `REQUIRE_POSTGRES=true` | في الإنتاج يمنع الرجوع إلى SQLite |
| `GEMINI_API_KEY` و`APP_URL` | موجودان في `.env.example` كقيم فارغة |

> **تحذير أمني:** في `server/db.ts` توجد كلمة مرور افتراضية ثابتة تُستخدم لحساب مالك المنصة إذا لم تضبط `PLATFORM_OWNER_INIT_PASSWORD`. على أي قاعدة جديدة اضبط المتغير قبل أول تشغيل، وغيّر كلمة المرور فورًا إن سبق تشغيل النظام بدونه. لم أعدّل هذا الكود في هذه النسخة لأنه خارج نطاق التصميم، لكنه يستحق مراجعتك.

## التشغيل

```bash
npm run dev          # tsx server.ts (الخادم والواجهة)
npm run build        # vite build إلى dist/
npm run lint         # tsc --noEmit
```

ينشئ الخادم مجلد `data/` وقاعدة SQLite جديدة تلقائيًا عند أول تشغيل إن لم تكن موجودة.

## الاختبارات

```bash
npm test
```

يشغّل ثلاثة ملفات في `tests/`: الأمان، وسير العمل، وتوافق PostgreSQL. اختبارا الأمان وسير العمل يشغّلان الخادم محليًا ويستخدمان قاعدة `data/alrahman.db` في المجلد الحالي، **فلا تشغّلهما أبدًا في مجلد فيه قاعدة بيانات إنتاج حقيقية.** شغّلهما على نسخة نظيفة من الأرشيف.

## PostgreSQL

الملفات في `scripts/` (تصدير SQLite وترحيله والتحقق منه) و`server/postgres_schema.sql` موجودة للترحيل. لا تشغّلها على قاعدة إنتاج دون نسخة احتياطية ومراجعة. السكربت يرفض العمل بلا `DATABASE_URL`، ويقارن اسم القاعدة بـ`EXPECTED_TARGET_DB` إن ضُبط.

## أندرويد

```bash
npm run build:android    # vite build ثم cap sync android
```

مجلد `android/assets/public` يحتوي ناتج بناء قديم وسيُستبدل عند المزامنة.

## ما تغيّر في هذه النسخة (واجهة فقط)

- نظام ألوان كحلي وأزرق وذهبي في `src/index.css`، مع تعريف سلالم `navy` و`gold` التي كانت مستخدمة في الكود دون تعريف.
- ترويسة وتنقل وتبويبات إدارة بحالات نشطة وسهولة وصول أفضل (`Header.tsx` و`AdminDashboard.tsx`).
- مكونان جديدان: `Toast.tsx` و`Skeleton.tsx`. الـToast مركّب في `main.tsx` ومستخدم في بوابة السائق وصفحة الحساب بدل `alert()`، أما `Skeleton` فغير مربوط بأي شاشة بعد.
- إصلاح اتجاه أيقونات في `BookingPage.tsx`، وتحسينات للجداول والنماذج على الهاتف.
- لم تتغير ملفات الخادم أو المصادقة أو قاعدة البيانات أو الاختبارات.

## ما لم يُنفَّذ (غير مختبَر)

لم يتوفر `npm install` ولا إنترنت أثناء التعديل، لذلك **لم يُشغَّل** أي مما يلي:

- `npm run lint` و`npm run build` و`npm test`
- تشغيل التطبيق في متصفح وفحص Console والتنقل وتسجيل الدخول والصلاحيات
- فحص المظهر على الهاتف والكمبيوتر وفي RTL وLTR

الذي تم فحصه فقط هو صحة الصياغة (syntax) في الملفات المعدّلة ومراجعة الفروقات يدويًا.

## ما استُثني من الأرشيف عمدًا

- كل ملفات `.env` الحقيقية (بقي `.env.example` وفيه قيم وهمية فقط).
- `data/alrahman.db` وملفاتها الجانبية، و`data/migration_to_postgres.sql` (تصدير لبيانات حقيقية).
- مجلد `backups/` كله (نسخ احتياطية لقاعدة البيانات).
- `node_modules/` و`dist/`.
